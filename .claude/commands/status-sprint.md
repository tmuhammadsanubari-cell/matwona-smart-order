Baca `docs/BACKLOG.md` dan ringkas:

1. Per sprint: jumlah task selesai / total, dan persentase.
2. Task yang belum selesai di sprint berjalan, urut berdasarkan prioritas (Must → Should → Could) dan dependensi.
3. Task Must Have untuk milestone terdekat (MVP minggu 9, Beta minggu 15) yang berisiko terlambat.
4. Cek cepat di kode: untuk task yang dicentang selesai, pastikan file/modul utamanya memang ada. Laporkan jika ada yang dicentang tapi tidak ditemukan.
5. Rekomendasikan 3 task berikutnya beserta alasan singkat.

Tampilkan dalam tabel ringkas. Jangan mengubah file apa pun.
